1 · What is Go

A simple, fast language made by Google

Go (or Golang) came out of Google in 2009. It was built to be easy to read, quick to build and fast to run. It has few features on purpose, so there's usually one obvious way to do something.

CompiledTurned into a ready-to-run file before it runs.
Statically typedEvery variable has a fixed type, checked before running.
Garbage collectedCleans up unused memory for you, like Ruby.
GoroutinesDoing many things at once is easy and cheap.
TrustedDocker, Kubernetes and Terraform are written in Go.

Go is a small, strict, fast language that big infrastructure tools rely on.

2 · Why Go

Why it's worth learning

For our services

  • Fast: often several times faster than Ruby for heavy work.
  • Cheaper: uses much less memory, so fewer servers.
  • Many things at once is built in.
  • Easy deploys: copy one file and run it.

For us

  • Fewer production surprises: many bugs are caught early.
  • Easy to read anyone's code: one style for everyone.
  • Small language: learn most of it in a few weeks.

Ruby is great for building quickly; Go is great when speed, cost and scale matter.

3 · The big difference

Interpreted vs compiled

Ruby

Interpreted: read and run line by line, every time it runs.

Go

Compiled: translated once, in advance, into one ready-to-run file.

Think of a kitchen. Ruby reads the recipe while it cooks, so you need the cook and the recipe in every kitchen. Go cooks the meal in advance and hands you a packed box. You can serve it instantly and carry it anywhere.

Ruby
ruby app.rb   # Ruby must be installed to run this
Go
go build -o app   // make the packed box once
./app             // run it, no Go needed

Ruby translates while running; Go translates once and gives you a finished program.

4 · Fundamentals

8 ideas that make Go, Go

These are also the topics in our practice repo.

4.1Types are fixed

Ruby

A variable can hold anything, and change later.

Go

A variable has one type forever, checked before running.

Think of labelled jars. A jar labelled "sugar" can't hold salt. Ruby lets you swap and you find out when you taste the cake. Go stops you before you start baking.

Ruby
age = 30
age = "thirty"   # allowed
Go
age := 30
age = "thirty"   // won't build

Go catches type mix-ups before the program runs.

4.2One file you can run anywhere

Ruby

Every server needs Ruby and your gems installed.

Go

You build one file. The server just runs it.

Think of moving house. Ruby is shipping the furniture as flat-pack plus the tools to build it. Go is shipping it already built.

Ruby
bundle install
ruby app.rb
Go
go build -o app
./app

Build once, copy one file, run it anywhere.

4.3Functions can return two values

Ruby

Returns one array, like [333, 1], then unpacks it.

Go

Really returns two separate values: 333 and 1.

Think of a shop. Ruby hands you one bag with two items inside. Go hands you the two items, one in each hand.

Ruby
def split(total, people)
  [total / people, total % people]
end
each, left = split(1000, 3)
Go
func Split(total, people int) (int, int) {
    return total / people, total % people
}
each, left := Split(1000, 3)  // 333, 1

Ruby packs values into an array; Go returns separate values and you must take both.

4.4Errors are returned, not thrown

Ruby

Stops and shouts (raise). Someone else must catch it (rescue).

Go

Quietly hands you a note: "this went wrong". You read it on the next line.

Think of a restaurant. In Ruby, if the dish is sold out, a waiter runs out shouting and hopes someone deals with it. In Go, the waiter always brings two things: your food and a note. Blank note means all good. You check the note before you eat.

Ruby
begin
  amount = Integer("12a")
rescue ArgumentError => e
  puts "bad amount"
end
Go
amount, err := strconv.Atoi("12a")
if err != nil {      // is there a problem note?
    fmt.Println("bad amount")
    return
}

Ruby throws problems; Go returns them, and you check if err != nil right away.

4.5Structs instead of classes

Ruby

Classes, with inheritance (a class can extend another).

Go

Structs: a set of fields, with methods attached. No inheritance.

Think of a paper form. A struct is a form with fixed boxes, like Owner and Balance. Methods are the actions you can do with that form, like Deposit.

Ruby
class Account
  attr_accessor :owner, :balance
end
Go
type Account struct {
    Owner   string
    Balance int
}

Two small rules: a Capital name is public, a lowercase one is private. And *Account means "change the real account, not a photocopy".

A struct is a form with fixed fields; methods are what you can do with it.

4.6Interfaces

Ruby

"If it quacks like a duck, it's a duck." Checked when the code runs.

Go

Same idea, but checked before running.

Think of a job ad that says "must be able to drive". Anyone who can drive qualifies, with no special certificate. Go checks that every applicant really can drive before the work starts.

Ruby
# anything with monthly_cents works
bills.sum(&:monthly_cents)
Go
type Bill interface {
    MonthlyCents() int   // "must be able to do this"
}

An interface is a list of skills; any type with those skills fits.

4.7Doing many things at once

Ruby

Mostly one thing at a time. We add tools like Sidekiq for more.

Go

Put go in front of a call and it runs alongside everything else.

Think of waiters. One waiter serves tables one by one. Go gives you as many waiters as you need, and they're cheap. Each one is called a goroutine.

Ruby
send_email(user1)   # waits...
send_email(user2)   # ...then this
Go
go sendEmail(user1)   // starts now
go sendEmail(user2)   // also starts now

The word go starts work in the background; thousands at once is normal.

4.8The tools come in the box

Ruby

Add gems for formatting, testing and more.

Go

Formatting, testing and checking come with the language.

Think of buying a phone. With Ruby, you buy the charger and case separately. With Go, they're in the box.

Ruby
rubocop -a
rspec
Go
go fmt ./...    // tidy the code
go test ./...   // run the tests

Every Go project uses the same built-in commands.

5 · Go vs Ruby

Side by side

TopicRubyGo
Runs byReading code while runningA pre-built program file
SpeedFine for most appsMuch faster for heavy work
MemoryHigherMuch lower
Bugs foundMostly while runningMany before running
Many things at onceLimited, extra toolsBuilt in
DeployRuby + gems on the serverCopy one file
Code styleMany waysOne way

Ruby is still better for

  • Quick prototypes and Rails apps.
  • Short code: users.map(&:email) is one line.
  • "Magic" like DSLs and metaprogramming.

What feels odd at first in Go

  • Writing if err != nil a lot.
  • Unused variables or imports are errors.
  • No map or select: you write a loop.

Go doesn't replace Ruby; it's the better tool when speed, memory or scale matter.

7 · Hands-on

Let's write some Go

Each folder in the repo has a short lesson (CONCEPT.md), the code you edit (exercise.go) and tests. The tests fail at first. You're done when they pass.

  1. Check Go is installed

    go version   # go1.25 or newer

  2. Clone the repo and make your branch

    git clone https://github.com/surya-km/go-learning-exercises.git
cd go-learning-exercises
git switch -c practice/your-name

  3. Run the first exercise's tests

    go test -v ./concepts/01-basics/   # fails at first, that's expected

  4. Edit exercise.go until the tests pass

    Save, run the tests, repeat. When the last line says ok, move to 02-variables.

Three errors you'll probably see today

undefined: fmt

Add import "fmt" under the package line.

declared and not used: x

Go doesn't allow unused variables or imports. Use them or delete them.

"./...." matched no packages

Too many dots. It's exactly three: ./...
